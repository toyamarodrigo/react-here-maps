# Issue Tracker: Local Markdown

Issues and PRDs for this repo live as markdown files in `.scratch/`.

## Layout

- One feature per directory: `.scratch/<feature-slug>/`
- The PRD is `.scratch/<feature-slug>/PRD.md`
- Implementation issues are `.scratch/<feature-slug>/issues/<NN>-<slug>.md`, numbered from `01`
- Conversation history is appended under a `## Comments` heading

## Issue metadata

Record issue state near the top of each issue file:

```markdown
Category: bug | enhancement
Status: needs-triage | needs-info | ready-for-agent | ready-for-human | wontfix
```

PRDs that are ready to split into issues should include:

```markdown
Status: ready-for-agent
```

## Publishing

When a skill says "publish to the issue tracker":

- For a PRD, create `.scratch/<feature-slug>/PRD.md`
- For an implementation issue, create `.scratch/<feature-slug>/issues/<NN>-<slug>.md`
- Create directories as needed
- Use relative markdown paths when referencing parent PRDs, blockers, or related issues

## Fetching

When a skill says "fetch the relevant ticket", read the referenced markdown
file. Users will normally pass a relative path such as
`.scratch/local-tracker/issues/01-localize-triage.md`.

## Comments

Append comments and triage notes to the bottom of the issue file:

```markdown
## Comments

> *This was generated by AI during triage.*

Comment body goes here.
```

Do not create hosted tracker comments or call hosted tracker CLIs for this repo.
